# 인공지능 구조 원리 교과서 — 자료 페이지

> ## ⚠ 동기화 규칙 — 가장 먼저 읽을 것
>
> `notebooks/` 아래의 `.ipynb` 는 **구글 드라이브 원본의 사본**이다.
>
> **드라이브 원본을 고치면 이 사본도 반드시 함께 고친다.**
>
> 이 규칙이 깨지면 점검 도구가 독자가 실제로 여는 것과 다른 코드를
> 검사하게 된다. 통과해도 아무 의미가 없어지고, 오히려 "점검하고
> 있다"는 잘못된 안심만 남는다.
>
> 사본에 검증 셀을 추가하지 말 것. 검증은 `checks/verify_results.py`
> 가 실행 결과를 바깥에서 읽어 판정한다.

공개 주소: <https://mlfundamentals.github.io/ai-structure/>

## 구성

```
index.html                 사이트 (data/*.json 을 읽어 상태를 표시)
links.yml                  점검 대상 URL — 사이트 섹션 2의 원본
notebooks.yml              실행·검증 대상과 판정 규칙
notebooks/                 드라이브 원본의 사본
checks/check_links.py      A. 링크 점검
checks/verify_results.py   C. 결과 검증
data/links.json            링크 점검 결과 (워크플로가 커밋)
data/status.json           STATUS 섹션 데이터 (워크플로가 커밋)
```

사이트에 보이는 내용을 바꿀 때는 `index.html` 이 아니라 `links.yml` 을
고친다. 점검 결과는 워크플로가 `data/` 에 써 넣고 페이지가 읽는다.

## 점검 체계

| | 주기 | 하는 일 |
|---|---|---|
| **A 링크** | 주 1회 (월요일) | `links.yml` 의 URL에 요청. 리다이렉트 최종 주소 기록 |
| **B 실행** | 월 1회 | 노트북 사본을 `nbconvert --execute` 로 실행 |
| **C 결과** | B와 함께 | 실행 결과의 핵심 수치가 기대 범위 안인지 판정 |
| **실환경** | 분기 1회 · 수동 | 사람이 실제로 열어 확인 |

### 403을 실패로 처리하지 않는다

위키백과·아마존·네이버는 자동화 요청을 차단한다. 403을 실패로
처리하면 매주 거짓 경보가 오고, 결국 알림을 통째로 무시하게 된다.
`403`·`429`·타임아웃은 **확인 필요**로만 기록하고, 워크플로를
실패시키는 것은 `404`·`410` 뿐이다.

차단이 확실한 사이트는 `links.yml` 에 `expect_block: true` 를 달아
아예 판정 대상에서 뺀다. **본문 실습 6건이 전부 여기 해당한다** —
네이버 단축 URL이고, GitHub Actions 러너는 미국 데이터센터 IP다.
이 6건은 자동 점검으로는 확인되지 않으므로, 분기별 실환경 점검에서
사람이 직접 연다.

### ⚠ CI는 Colab보다 엄격하다 — 그게 목적이다

Colab은 기존 노트북이 깨지지 않도록 `TF_USE_LEGACY_KERAS=1` 같은 호환
설정을 켜 두는 경우가 있다. 그 상태에서는 Keras 2에서만 동작하는 옛 API
(예: `optimizer.minimize()`)가 그대로 돈다.

**CI에는 그 설정을 켜지 말 것.** CI가 먼저 실패해 주는 것이 이 점검의
목적이다. Colab이 호환 스위치를 내리는 날 독자 환경이 한꺼번에 깨지는데,
그 전에 알려 주는 유일한 장치가 이 워크플로다.

"CI에서만 실패한다"는 것은 정상이 아니라 **경보**다. 워크플로에
`TF_USE_LEGACY_KERAS` 를 추가해 통과시키지 말고, 노트북 코드를
새 API로 고쳐 양쪽에서 돌게 만든다. (예: `optimizer.minimize(cost, var_list)`
→ `tf.GradientTape` + `optimizer.apply_gradients()`. 후자는 Keras 2에도
있으므로 옛 환경에서도 그대로 동작한다.)

### ⚠ 85쪽만 판정 방향이 반대다

85쪽 퍼셉트론 XOR은 **실패를 보여주는 실습**이다. 천 번을 학습시켜도
오차가 줄지 않는 것이 정상이고, 그것이 다층 퍼셉트론으로 넘어가는
근거다.

라이브러리 기본값이 바뀌어 **우연히 학습에 성공해 버리면 본문 논지가
정반대로 뒤집힌다.** 그래서 이 예제만 "성공하면 경보"다.

`notebooks.yml` 의 `practice-085` 에 `assert: {lt: 0.75}` 로 적혀
있다. 나머지 넷과 부등호 방향이 반대라 버그로 보이지만, **의도된
것이다.** 뒤집지 말 것.

## 운영 원칙

1. **책을 고치지 말고 페이지를 고친다.** 링크가 죽거나 코드가 낡으면
   사이트에서 대응하고, 본문 수정은 다음 쇄로 미룬다.
2. **자료실 코드가 항상 최신이다.** 책과 다를 수 있음을 명시하고,
   고친 부분에 주석을 단다.
3. **정오표는 쇄별로 구분한다.**
4. **빈 섹션도 남긴다.** "아직 보고된 오류가 없습니다"가 섹션을
   감추는 것보다 신뢰를 준다.
5. **점검 결과를 숨기지 않는다.** 관리되고 있다는 사실 자체가 신호다.
